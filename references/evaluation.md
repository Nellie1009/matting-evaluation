# 逐图评估操作

## 定位和证据

1. 清点工作表、有效数据行、模型、参考图和生成图。支持浮动 drawing、单元格图片、DISPIMG、图片链接和本地路径。必要时只读解析 ZIP/XML：worksheet relationships → drawing anchors（行列从 0 开始）→ image relationships → media。对同一单元格多张图片先查清角色，不能挑一张猜测。
2. 以参考图 ID、原始字节哈希或明确任务标识建立任务ID；不得按固定每15行分组。参考图相同但分辨率/压缩不同，需目视确认后合并；仅 Prompt 相同不能判定同一任务。以任务ID、模型、平台/设置、运行ID保留每次结果的唯一对应关系。
3. 不同平台、价格配置、分辨率设置不是自动可合并的同一模型实验条件。若表中这些条件影响可比性，分析显示为独立系列，如“模型｜平台｜配置”；重复运行才合并为任务内均值。只缺少一条结果不能删整个模型。
4. 写出可续做清单：行地址、模型/系列、任务ID、输入/输出图片路径、格式、尺寸、alpha检查、两标签、六评分、简短依据、复核状态。每完成一批保存，继续下一批，不等用户反复催促。

## Alpha 检查

读取原始嵌入图/实际结果文件的透明能力与 alpha 分布（RGBA、LA、palette+tRNS 都可能透明）。RGB/JPEG 或全不透明 alpha 为 0；含 alpha 通道不等于真实透明。

在至少两种对比底色上合成观察，确认人物外部本应移除的背景有实际透明区域，而不是只有角落一个透明像素、带 alpha 的棋盘格截图或不相关孔洞。不要固定“透明面积超过5%”之类阈值：人物占比差异很大。有效透明输出可得 4，局部背景残留另扣主体识别/精细度。棋盘格已经烘焙到 RGB 中记 0。只有截图而无法取实际 alpha 时标待核验，不能凭灰白方格确认 4。若已导出格式本身为不透明，按可观察文件评 0，同时记录“仅检查到该导出文件，无法证实平台原始结果”。

## 视觉检查的两个层次

- 先看全图：所有完整人物、半身/头像排除、独立框/建筑/植物/地台/水印、主体缺损、裁切、动作及比例。穿戴、直接持有或与身体连接的物体通常属人物；独立环境装饰属背景。魔法、漂浮装饰等归属有歧义时，先结合参考图和用户规则统一一次，并记录，不随模型改变标准。
- 每条都看原分辨率或足以分辨的放大局部：发梢及发丝镂空、指缝、袖口、裙摆、鞋尖/鞋跟、翅膀羽缘、蕾丝/半透明部位，以及面部、饰品、绘画笔触。接触表只用于排序与初筛，放大核查不能仅针对“好模型”。
- 精细度在深、浅底上检查毛边、色污染、缺失、硬切和锯齿。颜色在同一显示条件下比较主体不透明内部区域，避免把合成底改变半透明像素的视觉效果直接认作改色。
- 比较颜色和结构时先等比配准主体。自动色差、特征配准和像素差仅是辅助：JPEG压缩、抗锯齿、透明去污染、位移都会引入像素差；不能用一个统计量代替视觉评分，也不能通过白平衡/滤镜掩盖原本的色差。

主体选择错误与轮廓去除质量分别判断。只保留白底但轮廓和主体正确时，透明维度为0，并非其他维度一律0；大头像未排除，不能因此直接把完整主体精细度打0。4分不是“看起来挺好”，必须符合评分标准。

若参考图没有合格完整人物、主体归属无法确定、图片损坏或生成失败，完成其他可评记录，保留该条具体缺失原因；不能擅自创造空主体评分规则。用户未给出失败计分政策时，缺失项不作真实0分。
