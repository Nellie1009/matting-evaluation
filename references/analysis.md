# 数据分析：引用驱动，保留用户的表格模式

## 数据契约与口径

- 源评分只保留一份，全部分析引用它。先建实际列映射，不依赖 H:P 位置。至少映射任务ID、模型/比较系列、六评分、合计、评测状态；平台/设置不同的系列先明确分开。
- 原始逐次评分是人工判断输入；合计、完成状态、所有汇总和排名为公式。平均分保留原始精度，单元格显示两位小数；整数分和排名显示整数。不先四舍五入再平均或排名。
- 只纳入六维完整的“已评”记录；0 是有效低分，空白/待评/缺失不等于0。任务与模型重复记录不静默挑第一条：保留每次，先同任务同系列求均值，再对任务等权汇总。
- 每个任务/系列的明细格：先 `COUNTIFS` 检查有已评记录，再 `AVERAGEIFS`，没有则 `""`。公式示意：`=IF(COUNTIFS(TaskRange,$B3,ModelRange,D$2,StatusRange,"已评")=0,"",AVERAGEIFS(TotalRange,TaskRange,$B3,ModelRange,D$2,StatusRange,"已评"))`。范围固定为实际数据界限，勿使用整列或给不同长度范围。
- 覆盖数按有完整评分的任务数计算，不按运行数；同时提供运行数/缺失数。默认综合排名只包含覆盖全部任务的系列，缺失系列仍显示已评均分和覆盖数，排名留空。不用不同任务集合的均分作无说明的总排名。可按用户指定改为所有模型共同任务口径，并标明样本量。

## 表格模式

有用户模板时匹配表头填入公式，避免新增无必要的sheet；只有生成结果sheet时新增一个 `数据分析`，依下列顺序安排区块，复用同一任务×系列矩阵。

1. **任务总分对比**：行=所有任务，列=任务平均分及所有实际模型/系列；追加平均得分、已评任务数、综合排名。任务平均分为当行各系列任务均值的平均。全表平均为系列均分的平均，不让重复运行变相加权。样本不齐时单独标注覆盖，不能暗示完全可比。
2. **按厂商排列**：按用户既有的 doubao、gemini、gpt 等分组展示相同数据。不能把API平台当作模型厂商；不能漏掉 gpt-image-2。分组区的任务平均分及综合排名引用全体统计，保持与总表同口径。
3. **各模型六维任务明细**：每个系列一个区块，行=任务1…N，列=六维；追加各维度均分。任务内先平均重复运行，再按任务等权求维度均分。
4. **评测维度分析**：行=所有系列，列=六维，值引用对应明细区的维度均分；末行维度平均得分。定性结论以实际观察和分数为依据：说明背景残留、边缘毛边/杂色、局部改色、重绘、裁切等代表性问题，并能定位任务/源行。没有可核查视觉依据时只描述量化表现，不虚构原因。
5. **任务标签分类**：每任务一行，列=主体复杂度、主体与背景融合度、综合难度。前两者引用已评参考图标签，同任务须一致；表头括号中的类别数量用 COUNTIF 联动计算，不能复制上次的“4低3中3高”。
6. **评测集维度分析**：分别按主体复杂度、主体与背景融合度、综合难度做三块表；行=系列，列=低/中/高，值为相应标签任务总分的等权平均（满分24）。类别没有任务时留空并注明样本数0，不当作低分；末行跨系列均分。同一套标签必须同时驱动分类表和三块统计表。

用户提供的历史模板中，综合难度未明确定义公式。为复现已采用的分组，默认将低/中/高编码为1/2/3，两个标签平均后向下取整，再映射回低/中/高：低+中→低，低+高→中，中+高→中，高+高→高。公式如 `=INDEX({"低","中","高"},INT((MATCH(C3,{"低","中","高"},0)+MATCH(D3,{"低","中","高"},0))/2))`。**这是可替换的分析约定，不是用户给出的六维评分标准**；在工作簿非数据表头处简短说明。用户指定其他规则即替换。没有依据时不得用模型得分反向定义输入复杂度。

## 极值底色

- 最高分绿底 `#C6EFCE`，最低分红底 `#FFC7CE`，其余评分白底 `#FFFFFF`。并列全部标；空白不标；整组同分保持白色（避免既最高又最低）。表头和行标签沿用模板样式。
- 使用条件格式，让分数修改后自动更新，清理目标数据区内冲突的旧极值规则和旧红绿静态填色。不要清除不相关格式。
- 总分任务行：同一任务的所有系列横向比较；厂商分组复制同一全体极值口径，不在分组里另算最高最低。
- 模型平均分行及维度/分类统计列：在同一统计项的系列间比较，排除因样本不齐而不可比的系列；覆盖信息必须展示。各模型任务明细：同维度在各任务之间比较，均分行则与其他模型同维度比较。别把不同维度横向最高当成“最佳模型”。
- 排名数值越小越好，第一名绿、最末名红，空排名白；覆盖数和统计基准/平均值不参与分数极值比较。
- 连续比较范围示例：绿 `=AND(ISNUMBER(D3),MAX($D3:$R3)>MIN($D3:$R3),D3=MAX($D3:$R3))`，红将最后一项改为 MIN。若部分系列被覆盖条件排除，用 COUNTIFS/辅助资格值限制参评集合，不让待评均分影响极值。

## 公式计划工具

`python scripts/analysis_plan.py mapping.json --out plan.json` 只生成JSON，不读写xlsx。mapping 包含真实源sheet、first_row/last_row、columns（task/model/status/total/scores）、models、tasks、labels（每任务复杂度与融合度）。模型名若按平台/设置拆分，源 model 列映射到对应的比较系列列。

例如（列字母、行界限和清单均需由实际文件替换）：

```json
{
  "sheet": "生成结果",
  "first_row": 2,
  "last_row": 8,
  "columns": {
    "task": "Q", "model": "E", "status": "R", "total": "P",
    "scores": ["J", "K", "L", "M", "N", "O"],
    "complexity": "H", "fusion": "I"
  },
  "models": ["模型A", "模型B"],
  "tasks": ["T001", "T002"],
  "labels": [["低", "低"], ["高", "高"]]
}
```

若源表已有标签，columns 另传 `complexity` 和 `fusion` 的实际列字母，工具用 INDEX/MATCH 引用；未映射时 labels 成为可编辑的分析输入，调用方需与源表保持唯一权威来源。使用前先验证每个任务的标签一致，不能任意选某个冲突标签。

输出 `cells` 中 `value` 写为输入文本/值，`formula` 写为真正的Excel公式；`highlights` 是条件格式的比较范围及语义，`eligible_range` 表示覆盖数资格约束；必须将它们实现为条件格式，不能只导出 JSON 或靠静态颜色冒充联动。模型厂商分组及模板特定位置由调用方按实际表头补齐。工具生成的是无模板时的基础布局，不会强行重排用户模板。

极值计划字段：`range` 为着色目标；`comparison_range` 存在时应以它作为比较值集合，否则使用目标范围；`eligible_range` 与比较值逐项对应；`eligible_cell` 存在时是当前单独目标格的资格值，否则取同位置资格值；资格阈值取 `required_count_cell` 指向的单元格，未提供时取 `required_count` 数值。所有比较范围和阈值引用绝对锁定，目标格保持相对引用。目标本身和参评值都要满足资格；分组同分保持白底。比如以覆盖数10为条件的绿色规则可用 `AND(ISNUMBER(C3),I3=10,COUNTIFS($I$3:$I$17,10,$C$3:$C$17,">"&C3)=0,COUNTIFS($I$3:$I$17,10,$C$3:$C$17,"<"&C3)>0)`；红色交换大小方向。排名按 reverse 反转颜色。

工具用 `SUMIFS/COUNTIFS` 实现多条件均值，与完整有效记录上的 AVERAGEIFS 等价。若表格计算库的 AVERAGEIFS 多条件返回 `t.reduce is not a function` 等非Excel错误字符串，先在小范围确认，再使用此等价式；不能把报错文字当作数值写回或声称重算通过。

分类样本数用 `SUMPRODUCT((标签范围=类别)*ISNUMBER(任务均分范围))`，分类均值用对应 SUMIF 除此样本数，无样本返回空白。部分计算库会将公式空字符串误计入 COUNTIFS 的 `>=0` 与 `<>` 联合条件，因此不要用该组合判断任务是否有效。

## 验证

从源评分独立算一组任务合计、一个模型均分、一个维度和一个分类均值，与公式值核对；检查重复运行没有加权偏差、缺失没变0、所有模型出现、并列排名（1,1,3）正确、类别计数与任务数一致。重算后检查错误值。对一个非满分单元格做临时改分，确认总分→任务矩阵→均分/排名/类别分析→极值色都变化；恢复并再次重算。渲染主要区块，确认零显示为0、数字不带尾随小数点、长模型名不被截断。
